# B18000 61维真机采集：完整启动流程

此版本继承取消额外补偿的控制器。没有更改模型、PD、关节映射、50 Hz周期和保护阈值。
助手不会执行本页的使能、标定或动作命令。以下由操作者执行。

## 0. 部署（Windows PowerShell，无电机指令）

```powershell
& 'E:\11\gym_dog\tools\capture61\deploy.ps1' -JetsonIp 172.19.18.130
```

必须看到离线测试通过及 `Build complete. No controller, motors or motion started.`。
SSH超时或测试失败时不要继续。部署复制现有 no-extra-compensation 源码到独立工作区，
上传采集代码，运行模拟设备的离线测试并构建，不启动控制器。

## 1. 两个终端都加载同一环境

```bash
ssh jetson@172.19.18.130
source /opt/ros/humble/setup.bash
source /home/jetson/deploy_staging/b18000-capture61-20260921/install/setup.bash
export ROS_DOMAIN_ID=99
ros2 pkg prefix mydog_policy
```

路径必须是 `/home/jetson/deploy_staging/b18000-capture61-20260921/install/mydog_policy`。

## 2. 终端A：创建采集会话并启动站立（会使能电机）

先支撑好机器人，停止旧控制器，保证只有一个控制器；Ctrl+C不等于电机断电。

```bash
CAPTURE_SESSION="/home/jetson/mydog_ros2_ws/log/capture61/$(date +%Y%m%d_%H%M%S)"
mkdir -p "$CAPTURE_SESSION"
printf '%s\n' "$CAPTURE_SESSION" > /tmp/mydog_capture61_session
ros2 launch mydog_policy rs01_capture61.launch.py \
  enable_send:=true stand_only:=false \
  capture_dir:="$CAPTURE_SESSION" \
  debug_csv_path:="$CAPTURE_SESSION/controller.csv"
```

保持终端A运行。默认launch参数原本是 `enable_send=false, stand_only=true`；
上面的显式参数由操作者授权站立。采集器不会自动arm或行走。

## 3. 终端B：检查站立并标定

```bash
ros2 topic echo /mydog/model18000/status std_msgs/msg/String --field data
```

等待 `mode=ready`、`walk_start_stable=true`，确认机身水平、四脚承重静止。
Ctrl+C仅退出终端B的显示，然后执行：

```bash
ros2 service call /mydog/model18000/calibrate_imu std_srvs/srv/SetBool '{data: true}'
ros2 topic echo /mydog/model18000/status std_msgs/msg/String --field data
```

保持静止至少5秒。确认 `imu_calibrated=true`、`calibration_state=complete`、
`timing_ready=true`、`heading_consistency_healthy=true`、`walk_start_stable=true`，
`capture_rows`持续增长、`capture_dropped=0`、`capture_error`为空。
Ctrl+C退出状态显示。不满足条件时不启动动作。

## 4. 终端B：每个工况独立保存

先定义脚本位置：

```bash
TRIAL=/home/jetson/deploy_staging/b18000-capture61-20260921/run_trial.sh
```

静止站立每次30秒；这些命令只读取CSV，不发送动作：

```bash
bash "$TRIAL" stand run01
bash "$TRIAL" stand run02
bash "$TRIAL" stand run03
```

以下每条会启动指定动作30秒，结束后解除行走授权、等待柔和回站。
每份CSV采集60秒，包含起步、动作与回站；分析动作时筛选 `mode=walk`。
逐条执行，上一条成功结束且机器人站稳后再执行下一条。失败不自动重试。

前进：vx=0.15 m/s。

```bash
bash "$TRIAL" forward run01
bash "$TRIAL" forward run02
bash "$TRIAL" forward run03
```

后退：vx=-0.10 m/s。

```bash
bash "$TRIAL" backward run01
bash "$TRIAL" backward run02
bash "$TRIAL" backward run03
```

左转/右转：wz=+0.20/-0.20 rad/s。

```bash
bash "$TRIAL" turn-left run01
bash "$TRIAL" turn-left run02
bash "$TRIAL" turn-left run03
bash "$TRIAL" turn-right run01
bash "$TRIAL" turn-right run02
bash "$TRIAL" turn-right run03
```

左移/右移：vy=+0.10/-0.10 m/s。

```bash
bash "$TRIAL" left run01
bash "$TRIAL" left run02
bash "$TRIAL" left run03
bash "$TRIAL" right run01
bash "$TRIAL" right run02
bash "$TRIAL" right run03
```

避免把整块移动命令一次性粘贴执行。也可单独预览（不连接ROS或硬件）：

```bash
ros2 run mydog_policy mydog_model18000_sequence --action forward --speed 0.15 --seconds 30 --print-plan
```

## 5. 取消动作与结束采集

动作终端Ctrl+C，或另一个相同环境终端：

```bash
ros2 service call /mydog/model18000/arm std_srvs/srv/SetBool '{data: false}'
```

这是解除行走授权、回站，不是电机断电。失稳使用物理急停。
最后支撑好机身，按现场停机流程退出终端A控制器；正常退出会刷新采集文件。

查看数据：

```bash
cat /tmp/mydog_capture61_session
ls -lh "$(cat /tmp/mydog_capture61_session)"
```

## 文件、字段与已知边界

- `cycles.csv`：完整会话，每个成功完成的控制周期一行；异常周期见controller状态日志。
- `metadata.json`：模型完整contract、字段单位、关节顺序、坐标变换及缺失项。
- `capture_summary.json`：正常退出时写入，含行数、丢行数、写盘错误。
- `stand_run01.csv`、`forward_run01.csv`等：每组独立数据，配套JSON记录时间窗口及策略帧数。
- `controller.csv.status.jsonl`：故障、标定、时序、使能和保护状态。

记录原始/偏置修正后三轴gyro、IMU四元数/加速度/磁力/重力方向、姿态角，
原始及有效命令、heading、速度估计、逐腿接触/位置/速度、q/dq、完整61维obs、
裁剪前后action、限速后目标变化率、最终保护后的关节目标、扭矩/温度/错误码/反馈序号。

站立不执行策略，`policy_evaluated=false`；obs保留控制器实际发布的占位值，
raw_action等不存在的量写NaN，不伪造站立策略推理。前进等工况只分析
`policy_evaluated=true`的输入→输出链路。动作索引采用policy顺序FL,FR,RL,RR；
具名q/dq/target字段按FR,FL,RL,RR输出，metadata中有完整映射。

时间戳统一为主机monotonic，但IMU/电机时间是主机快照/接收时间转换，
不是真正设备采样时间，`acquisition_sync_verified=false`。同时保留原始wall时间、
电机board_tick、逐电机age。不得把sensor_skew当作已证明的物理采样偏差。
最终target是本周期提交给发送链路的目标，不是逐电机执行确认。

本版不提供独立100Hz原始IMU帧日志（只保留50Hz控制周期实际使用的快照），
也没有逐电机电流、stance score、外部GT和每腿期望接触schedule；这些未获取量
不以0冒充实测。外部GT必须另接定位设备。采集程序不校正安装角、不增加运动补偿。

已在Jetson完成模拟设备的ROS节点离线测试与构建；没有启动真机控制器。
这些测试不等于真机采集性能验收，首次运行仍需核对时序、capture_dropped及capture_error。
