# URDF4 V2 AMP + CTS 本轮修改与验收

以下记录是步态与速度联合验收：最优 PPO 候选为第100轮，12类动作中10类在全部6组复核中通过；预热网络为9类，联合验收未全部通过。不能把预热带来的动作恢复算作 AMP 从零学习成功。

用户随后明确要求先学步态、后做速度追踪，并自行启动30000轮。独立入口 `tools/urdf4_amp/train_cts_gait_first.py` 已关闭显式速度追踪奖励，从第100轮续训到总计30000轮，允许该阶段长训；保留原联合验收未通过状态，不生成虚假通过回执。新入口已在128环境实际完成100→103的3轮续训冒烟，结果见 `gait_first_smoke.json`。后文“长训未放行”均指原联合验收入口，本轮未代用户启动长训。

## 6. 文件变化

- `amp_cts_env.py`：完整RSI恢复；移除reset隐含零动作；恢复历史时不多消耗传感器采样；统一周期平均指令误差；足端几何仅诊断。
- `amp_cts_config.py`：先覆盖12类V2指令，关闭扰动；相邻帧AMP和有限保守PPO参数。
- `urdf4_amp_cts.py`：相邻状态AMP、内部指令缩放、PPO与学生辅助学习分离、固定预热策略保存恢复、长训契约校验。
- `prepare_cts_bootstrap.py` / `refit_cts_seed.py`：真实Gym控制记录、600完整状态快照、有限神经网络预热。初始actor仅依赖指令/相位/步态开关；其他状态输入权重先为0，PPO时允许学习，不在运行时查表。
- `evaluate_cts_behavior.py`：明确动作验收；`check_style_learning.py`兼容转发。
- `smoke_cts_isaac.py`：RSI、冻结预热模型、保存恢复、导出、两种CTS角色和AMP边界检查。
- `train_cts.sh`：只有通过的模型/代码/数据契约才允许长训。
- `play.py`：CTS冷启动先保持默认关节目标落地2 s，再执行学生网络；切指令更新观测，保留原生鼠标相机。

## 7. 参数与奖励

AMP权重2，20轮渐入；相邻46维状态构成92维，加3维指令，D输入95维。任务指令Huber损失权重0.5（线速度尺度0.08 m/s，转速0.20 rad/s），其余仅非法支撑−1、原始超峰扭矩−0.5、碰撞−1、动作变化−0.001、终止−10。不增加抬脚、姿态、关节轨迹等奖励。

CTS教师/学生环境3:1；学生编码器只做监督学习，PPO不更新。公共输入1020，打包训练输入1120，导出只读公共输入。PPO学习率1e-4、2 epochs、clip=0.05、entropy=0、动作噪声标准差初始0.05；相对预热网络的动作死区0.05、hinge系数100。约束在实际裁剪动作空间计算，不加入环境奖励。

## 11. 剩余限制与后续方向

专家Isaac Gym回放采用同一25帧速度统计，在5 s后统计的异常为：forward_slow 0.0323 m/s；left 0.0318 m/s；turn_right 0.0414 m/s；forward_right 0.0331 m/s。这证明存在指令标签与实际运动偏差，但不能用它免除学生验收。下一步应优先校准这些参考片段的实际速度/控制目标并保留V2原件，再重新做有限短训；不继续堆奖励或直接扩大长训。

该模型还没有证明连续0–0.6 m/s全向插值、任意动作切换、扰动鲁棒性、长时热安全、MuJoCo迁移或实机表现。验收统计不能替代现场视觉评判；目前不称为最终AMP步态策略。

实现参考：[LeggedGym-Ex AMP+CTS](https://github.com/lupinjia/LeggedGym-Ex/blob/main/rsl_rl/algorithms/ppo_cts_amp.py)、[AMP参考状态初始化](https://github.com/escontra/AMP_for_hardware)。结合当前RS01控制链实现，没有照搬A1物理参数。
